# PRD · SkillForge 通用 Prompt 简化器（增量 evo2-7 · 逻辑词/语气词过滤）

> 版本线：2.6.0-evo → 2.7.0-evo（版本号由主理人处理 `__init__`，本增量仅出文档，不改源码）。
> 约束：零新增 pip 运行时依赖；前端零构建（原生 HTML/CSS/JS）；`/api/simplify` 向后兼容。
> 范围**仅**限「通用 Prompt 简化器」：`prompt_simplifier.py` / `/api/simplify` / 前端「简化」视图。**不**动 `cleaner.py` / SKILL.md 清洗。
> 本增量**叠加于 v2.6 之上**：v2.6 的 9 类规则、PRESETS、保护机制（`_PROTECT`/`_restore`/`_PROTECT_WORDS`）一律沿用，不推翻。
> 硬契约（不可破坏）：`rules is None` 时后端走 `PRESETS`，其 `simplified_text` 必须**逐字等于 v2.5**（仅那 5 个基础类）。

---

## 1. 产品目标

- **G1（过滤更完整）**：在 v2.6 已覆盖「礼貌词/元评论/弱语气/冗余副词/示例」之上，补齐两类高频"思维痕迹"冗余——**逻辑连接词**与**句末语气词**，让"没什么用的词"基本清零。
- **G2（默认就更强）**：用户诉求"默认就去掉"。在**不破坏 `rules=None≡v2.5` 契约**的前提下，让前端默认勾选态与预设按钮即包含新规则类，达成"开箱即更强"。
- **G3（绝不伤指令）**：新增过滤必须严守"保留关键信息原则"——指令性动词、条件、参数、关键名词、否定词、代码示例一律不删，删后句子主干/指令仍在。

## 2. 用户故事

- US-1（作为提示词作者）：我希望简化器把"因此/所以/然而/首先/其次/总之/需要注意的是"这类连接词，以及"啊/呢/吧/嘛/呀"这类句末语气词也去掉，但"请**删除**所有注释"里的"删除"、"如果…则…"里的条件必须原样保留。
- US-2（作为普通用户）：我希望打开简化页默认就是"强过滤"——不用逐项勾选，"请/麻烦/能否/可以吗/帮我/谢谢/辛苦了/拜托"和逻辑词、语气词都直接被去掉，只留最关键的信息。
- US-3（作为进阶用户 / API 调用方）：我希望老接口（`{text}` 或 `{text, mode}` 不传 `rules`）行为**完全不变**，新过滤只是我主动勾选/显式传 `rules` 时的增量。

## 3. 新增规则类界定（核心交付）

### 3.1 `logical_connector` — 逻辑/序列/总结/过渡连接词（新增类）

**界定原则**：仅移除**不携带"要模型做什么"指令语义**的连接性词语——它们是"思考痕迹"而非"执行指令"。
**硬排除（保护，不纳入此类）**：条件/控制流标记——`如果 / 若 / 假如 / 假使 / 一旦 / 只要 / 只有 / 则 / 那么 / 否则 / 除非 / 不然 / 要不然`。这些携带"条件/分支"语义，必须保留。

**草案清单（按子类，待评审裁剪）**：

| 子类 | 词表草案 |
|---|---|
| 因果 | 因此、所以、故、故此、故而、因而、于是、由此可见、正因如此、由此看来 |
| 转折 | 然而、但是、不过、可是、却、反倒、相反、与之相反、话虽如此、尽管如此 |
| 顺承/序列 | 首先、其次、然后、接着、随后、最后、最终、一来、二来、再者、进而、与此同时 |
| 并列/增补 | 另外、此外、还有、另一方面、除此之外、以及、并且、同时 |
| 总结 | 总之、总而言之、总的来说、总的来讲、综上、综上所述、一言以蔽之、概括地说 |
| 解释/强调 | 其实、事实上、实际上、具体来说、具体而言、换句话说、换言之、也就是说、需要注意的是、值得一提的是、值得注意的是、明确地说、说白了、老实说、不瞒你说 |
| 话题 | 话说回来、言归正传、回到正题、顺便说一下、顺带一提、补充一下、多说一句、再说一句 |

> 实现方式：整词/短语级移除（同 `meta_comment`），并加**否定前瞻**（`_NEG_LOOKBEHIND`）避免"不**因此**"→"不"。清单与子类为草案，最终以架构师评审 + 回归用例为准（见 §7 Q2）。

### 3.2 `filler_particles` — 句末/插入语气词（新增类）

**界定原则**：去除位于句末或句中停顿处、仅表语气/舒缓、不承载信息的语气助词。

**草案清单（安全集，优先实现）**：

| 子类 | 词表草案 |
|---|---|
| 句末语气词（安全） | 啊、呢、吧、嘛、呀、哦、啦、哈、嗯、哟、嘞、咯、呗、呐、嗷、诶、额、呃、咪、噻、捏、哇、耶、喔、喏、啵 |
| 英文 filler（P2 变体，见 §5 P2） | um、uh、er、hmm、"you know"、"I mean"、"well,"、"like," |

> **`吗` 处理（谨慎）**：`吗` 是最常见疑问语气词，但"是否删除"会破坏真实疑问句（如"请告诉我是哪一步出错了吗？"→ 删"吗"变陈述）。**默认不纳入自动移除**，列为 §7 Q4 待拍板；若纳入，仅允许"句末 `吗？`/`吗。` 且前接非关键疑问词"时移除。

### 3.3 强化 `politeness`（在 v2.5 原表之上**扩展**，契约安全）

v2.5 原表保留不动；在**显式下发 `rules`（即前端路径）**时，追加扩展词表，补全用户点名的集合：

| 新增词（扩展集，仅 explicit 路径生效） | 说明 |
|---|---|
| 请（单字） | v2.5 仅 aggressive 去单字"请"；默认更强需覆盖 |
| 能否、可否、是否可以、可不可以 | 原表缺失 |
| 可以吗、行吗、好吗、方便吗、不介意的话、如果可以的话 | 原表缺失的软化尾缀 |
| 帮我、替我 | 用户点名"帮我" |
| 辛苦了、费心、劳驾、麻烦您、拜托你 | 用户点名"辛苦了/拜托/劳驾/费心" |
| 求你、劳烦（已有）、拜托（已有） | 补全 |

> **契约护栏（已裁定·已实现）**：扩展词表**不得**进入 `PRESETS`，且 `_rule_politeness` 仅在 `explicit=True`（前端显式传 `rules`）时叠加扩展集；`rules is None` 路径仍只用 v2.5 原 `_CN_FILLERS_*`/`_AGGRESSIVE` 表 → 输出逐字等于 v2.5。实现上由架构侧透传 `explicit = (rules is not None)`，契约安全。详见 §7 Q1。

## 4. 默认生效策略说明（重要）

**核心结论**：后端 `rules=None ≡ v2.5` 契约**不动**；"默认更强"完全由**前端显式发送 `rules`**达成。

- **后端**：`PRESETS` 维持 v2.5 的 5 类（`politeness/role_prefix/empty_items/duplicate_lines/blank_lines`），不新增 `logical_connector`/`filler_particles`。`rules is None` 行为零变化。新增两类**仅当用户显式勾选（下发 `rules`）时生效**。
- **前端现状（v2.6）**：`doSimplify` 始终下发 `{text, mode, rules}`，**从不**出现 `rules=None`；前端"保守"预设 = `{5 基础类}`，"激进" = 全 9 类。故"默认更强"只需改前端默认勾选态与预设定义。
- **增量动作（仅前端）**：
  1. `SIMPLIFY_RULE_IDS` 追加 `"logical_connector"`、`"filler_particles"`（共 11 类）。
  2. **默认勾选态（首次进入/无 localStorage）** 升级为"默认更强"集合 = 原 5 基础 + `logical_connector` + `filler_particles` + `meta_comment`（v2.6 已默认安全的类保留）。
  3. 「保守」预设按钮 = 上述"默认更强"集合（即用户要的"默认就去掉"）；「激进」预设 = 保守 + `hedging` + `redundant_adverbs` + `examples_trim`。
  4. 后端契约与前端解耦：无论前端怎么改默认，`rules is None` 的纯 API 调用方永远得到 v2.5 等价输出。

## 6. 保留关键信息原则（硬约束）

新增过滤**必须**满足以下不变量；任一条违反即判回归失败：

1. **指令性动词不删**：删除/提取/过滤/生成/检查/创建/返回/禁止/务必/确保… 等承载"动作"的词，绝不因连接词/语气词匹配而被移除（连接词与动词为不同整词，天然不重叠；靠整词匹配保障）。
2. **条件标记保护**：`如果/若/则/否则/除非/只要/只有/一旦` 等**不纳入** `logical_connector`，保留分支语义。
3. **参数与关键名词保护**：变量名、API 名、路径、数字、专名靠"整词匹配"不误伤；代码块/行内代码/URL 复用 `_PROTECT`/`_restore` 冻结（P0-2 继承 v2.6 保护）。
4. **否定词保护**：`不/没/别/未/无/莫/非/勿` 前导的连接词/语气词移除加否定前瞻（`_NEG_LOOKBEHIND`），避免"不**因此**"→"不"。
5. **代码示例零改动**：fenced code / 行内 code / URL 段在 `_protect` 后整体占位，新增规则作用其外，还原后逐字节不变。

> 自检口诀：删后通读，若"模型该做什么"仍清晰、条件/否定/参数/代码俱在，则通过。
